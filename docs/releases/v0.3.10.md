# Arco 0.3.10

Arco 0.3.10 fixes captures that silently stopped mid-meeting.

## Fixes

- Removes the app-level Doubao response watchdog. The optimized endpoint only sends packets when results change, so a quiet meeting looked like a dead socket and the watchdog kept reconnecting healthy connections. The WebSocket heartbeat already catches genuinely half-open sockets.
- Treats provider session errors as reconnectable. A reconnect gap longer than the provider's 8s packet-wait timeout (45000081) and provider-busy responses (55000031) now reconnect instead of killing the channel; only credential rejections stay fatal.
- Removes the three-strike retry budget that abandoned a channel after repeated stalls. With disk-backed audio buffering and a 5s backoff cap, a channel now rides out an outage instead of ending the whole capture when both channels gave up.

## Validation

- Fatal-classification tests now cover 45000081 and 55000031 as reconnectable.
- Backlog-preservation tests drive reconnects through the heartbeat path instead of the removed watchdog.
- All Rust core and integration tests pass; Clippy is clean with warnings denied.
