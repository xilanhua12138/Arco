# Arco 0.3.2

Arco 0.3.2 fixes long-running Doubao transcription stalls and prevents a closed transcription pipe from terminating the native macOS app.

## Fixes

- Keeps consuming recorder audio while Doubao is connecting, backing off, or replaying after a disconnect, so one stalled provider can no longer block the shared capture pipeline.
- Moves reconnect backlog PCM into an anonymous temporary-file spool instead of allowing an unbounded in-memory queue to grow during an outage.
- Replays every unconfirmed audio packet in source order at a provider-safe 2x catch-up rate, while continuing to accept new live audio.
- Resets reconnect backoff after provider progress and reclaims temporary spool storage as soon as confirmed audio catches up.
- Preserves the optimized `bigmodel_async` two-pass recognition, speaker separation, heartbeat, final-flush, and cross-channel timestamp behavior.
- Ignores process-wide `SIGPIPE` at native app startup so a closed worker pipe surfaces as a recoverable write error rather than exiting Arco.

## Validation

- Adds red-first regression coverage for reconnect backpressure, disk-backed ordered replay, spool reclamation, retry reset, and broken-pipe survival.
- Passes Rust formatting and Clippy with warnings denied across all targets and features.
- Passes the Rust audio runtime, core, capture, backend, controller, FFI, and parser test suites.
- Passes all native SwiftUI contract executables, recorder self-test, and local transcription self-tests.
- Builds and signs the complete native macOS application with all four isolated transcription workers and passes the release bundle boundary checks.
