# Arco 0.3.4

Arco 0.3.4 fixes a Doubao recovery loop that could leave live transcription permanently rewriting one stale row while old audio accumulated after repeated provider stalls.

## Fixes

- Aligns Doubao stream recovery with LiveKit's segment lifecycle: tentative text replaces the current edge, finalized utterances commit durable rows, and a disconnected channel clears its stale tentative edge before reconnecting.
- Retains only audio that has not yet been sent. Already-sent frames advance the stream watermark instead of being replayed into every replacement WebSocket and multiplying the backlog.
- Limits each stream to three consecutive recovery attempts. Only finalized transcript progress resets that budget; connection success, acknowledgements, and ordinary responses do not conceal a stalled provider.
- Keeps the transcript viewport following changes to the live edge, including tentative text replacement and newly finalized rows, while preserving manual scroll position when the reader moves away from the bottom.

## Validation

- Adds red-first tests for repeated silent provider connections, bounded retry recovery, sent-versus-unsent audio ownership, cross-channel watermark progress, stale tentative-edge cleanup, and live-edge following.
- Passes all Rust core and backend integration tests, SwiftUI/source-parity contracts, recorder self-test, local transcription self-test, formatting, and Clippy with warnings denied.
