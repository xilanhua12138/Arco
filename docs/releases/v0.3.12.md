# Arco 0.3.12

Arco 0.3.12 prevents Doubao reconnects and cross-channel ordering from hiding long stretches of a live meeting, and keeps the main window and floating transcript on the same faster data path.

## Fixes

- Replays every sent-but-unconfirmed Doubao audio frame after a disconnect, byte-for-byte and in order. Provider-confirmed audio is excluded, and repeated outages cannot duplicate the recovery backlog or silently advance the transcript watermark.
- Keeps finalized speech visible in the live sidecar while it waits for the other audio channel's ordering watermark, then removes the sidecar copy when the durable Markdown transcript commits it.
- Drives both the main transcript and floating transcript from the same active-meeting snapshot. The main-window refresh interval is reduced from 450 ms to 250 ms, and the sidecar-to-Markdown handoff suppresses only the exact duplicate event.
- Adds correlated structured session boundaries and Doubao replay, retry, catch-up, and watermark-gap diagnostics so a future missing interval can be traced to one capture session.

## Features

- Adds an in-app update check with release discovery, download progress, SHA-256 verification, code-signature validation, replacement, and relaunch.
- Adds the Arco product site and its validated GitHub Pages deployment workflow.

## Validation

- Regression tests cover partial acknowledgements, repeated disconnects, heartbeat recovery, pending finalized segments, sidecar handoff deduplication, active-meeting overlay parity, version comparison, and update-state failures.
- The full Rust, Swift, native-recorder, local-transcriber, localization, source-parity, and website validation suites pass.
- A real Doubao optimized-streaming run transcribed a 9.38-second Chinese sample, returned 15 result packets with a final result, and completed without provider errors or timeouts.
