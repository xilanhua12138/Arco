# Settings layout refinement

Use the supplied Typeless settings screenshot as the visual reference: a light gray navigation column, a white content surface, quiet icon-led group headings with thin dividers, and generous spacing between groups. Keep the four existing Arco destinations and all settings actions.

The sheet grows to fit the window (up to 1040 × 760 points). Setting labels use 14-point system type; helper text remains secondary. Shared controls use a 236-point track and 40-point menu height, stacking when the available width is insufficient. Row separators are replaced by section separators. Language uses a searchable autocomplete; finite choices use a non-editable select. Both use a full-width native field with left-aligned text and a right-edge chevron. It opens a matching-width, rounded floating list directly below the field, with selected-state marks on the right, and optional secondary labels. The whole field responds to clicks; arrow keys navigate, Return selects, Escape cancels, and clicking outside dismisses. The query never commits an arbitrary value. Disabled choices and capture locks remain enforced. Configuration destinations show ordinary status text with a separate Configure capsule button; they do not imitate selection fields or show dropdown/disclosure arrows. Ordinary actions use 32-point capsule buttons with regular 14-point type.

Language and shortcut help are visible. Detail destinations retain their parent selection and return action. The general page no longer overrides every child accessibility label with a shared container label.

Read-only inspection of the locally installed Typeless 2.6.0 bundle confirmed Electron/React with MUI: outlined Button actions, ButtonBase editable fields, Select/MenuItem for finite choices, and Autocomplete/OutlinedInput for searchable languages. The reference uses 10-pixel field corners and fully rounded action buttons. Lists sit 8 points below the field; language rows use 14/12-point primary/secondary type and a right-side 12-point selected mark, with white selected backgrounds. Arco implements the corresponding appearance with native controls. Capsule action borders and fills use matching circular corners; SwiftUI continuous corners produced visible vertical spurs at the two ends in a mounted native render.

The native settings control check exercises full-field hit targets, anchored list geometry, search and empty states, selection callbacks and refresh, Escape dismissal, popup teardown on navigation, and disabled meeting choices during capture. Set `ARCO_SETTINGS_SNAPSHOT` to a PNG path when running `ArcoSettingsControlContractTests` to render the mounted fixture for visual inspection.

Settings actions share `SettingsActionButtonStyle`, including embedded provider testing/refresh, recording and transcript folders, voice account connection, and output-editor actions. Storage capacity uses the same finite-choice control as other settings. Native selection fields draw a neutral focus treatment instead of AppKit’s blue ring.

In embedded provider settings, primary and secondary selection changes persist immediately through a separate change callback. The page remains open and connection testing is diagnostic, not a save gate. The settings footer has no Save Configuration button. The standalone setup flow retains its explicit finish step and connection-verification gate.
