# 会议录音存储

“设置 → 数据与隐私 → 保存会议录音”默认开启，默认目录为 `~/Music/Arco/Recordings`，容量上限为十进制 10 GB。上限可以改为 1、5、10、20、50、100 GB。修改目录和上限需要先结束录音，新设置从之后的录音开始生效；旧目录中的文件不会移动或删除。

保存 16 kHz 双声道 AAC/M4A（64 kbps，有损压缩），左声道为系统声音，右声道为麦克风。每场录音一个带时间和 UUID 的文件夹，内含会议关联信息 `recording.json` 和每 5 分钟一个的 `audio-NNNNNN.m4a`。暂停后续录产生另一个文件夹，两次录音通过元数据中的 meeting ID 关联。

实测 60 秒音频为 505,845 字节，估算每小时约 30 MB：30 分钟约 15 MB，2 小时约 60 MB，10 GB 约 330 小时。未压缩的实时 PCM 每小时为 230.4 MB。压缩大小随文件封装和录音内容略有变化。

每个新片段开始前预留空间，按创建时间清理最早的 Arco 音频片段。只处理带有 Arco 所有权标记的录音目录和指定名称的普通音频文件，不跟随符号链接删除，不删除转写与会议纪要。容量统计和清理仅针对当前选定目录中的录音；更换位置后的旧目录需要用户自行管理。

写入在独立、限制排队数量的队列中运行。目录不可写、空间不足或存储过慢时，音频归档停止并记录错误，已完成的片段保留；设置页显示错误。正常结束会封装最后一段 M4A。强制结束进程可能使最后一个未封装片段无法播放。旧版本没有保存的音频无法补回。

验证覆盖：AAC 编解码时长及声道、最早片段清理、空间不足、空与残缺 PCM、重复写入、只读目录、并发锁、符号链接、无关文件保护、设置保存与重载，以及真实 Rust 后端驱动的 SwiftUI 界面刷新。另使用真实 macOS 系统音频采集运行 5 秒并确认 M4A 可读。
