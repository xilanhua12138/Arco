# 邀请 Arco 入会

2026-09-11。本机安装目录为 `/Applications/Arco.app`；功能随 v0.3.25 发布。

## 体验与来源

“语音提问”改为“邀请 Arco 入会”，加入后可“请 Arco 离会”。混合模式同时接收系统声音和现场麦克风。参会动效位于独立的 300×392 悬浮卡片；无标题栏和红绿灯，22pt 圆角，仅顶部标题区域可拖动并保存位置，保持置顶。主界面和问答面板共用同一邀请会话，转写和问答保留原窗口。只有主动邀请后才显示卡片；已入会的主入口标为“Arco 已入会”，点击只找回同一个窗口。顶部收起只隐藏卡片，底部离会/取消会关闭卡片并断开语音、恢复麦克风，转写继续。停止会议和退出应用统一清理；启动失败不保留空卡片，语音连接失败保留明确的重试状态。未开始聆听时，邀请会先启动新的当前会议采集；历史里的邀请不续录到旧记录。

动效采用 [LiveKit Agents UI Aura 官方源码](https://github.com/livekit/components-js/blob/main/packages/shadcn/components/agents-ui/agent-audio-visualizer-aura.tsx) 的 GLSL 着色器及官方 hook 状态参数，移植到 Metal/MTKView。原 Canvas 仿制环已删除。没有引入网页运行时或 LiveKit 房间。着色器原始版权为 UNCRN LLC，Polyform Non-Resale 1.0.0 许可声明随资源保留；不是把该单独文件视为仓库其他文件的通用许可。播放端实际消费 PCM 的音量驱动说话状态，录音输入驱动聆听状态，Agent 委托驱动思考状态。支持 Reduce Motion，视觉更新最多 30fps，状态事件最多 10Hz。

参与规则参考 [Agora Meeting Copilot](https://github.com/zicojiao/agora-meeting-copilot/tree/e6c36428494ea4b28e573911c0a2574900b579ed)：默认安静，每轮被 Arco / Hey Arco / 阿可直接点名后回答。模型提示外另有真人转写驱动的播放门控，拒绝普通背景问题和句中提及名字。这不是独立声学唤醒器；识别延迟、名字误识别和真实重叠讲话仍是测试边界。

## 交互约定

用户任务分为会议记录、AI 参会和窗口展示。每个动作只改变对应状态，避免一个 toggle 同时承担邀请、离会和打开窗口。

| 当前状态 / 动作 | 用户看到的结果 | 音频与记录 |
| --- | --- | --- |
| 启动 Arco、打开历史、展开询问面板 | 无参会悬浮窗 | 不启动语音会话 |
| 开始聆听 | 会议转写开始 | 不自动邀请 AI |
| 首次点击邀请 | 单一悬浮窗显示准备 / 连接状态，可取消 | 若无录音，先开启新的当前会议 |
| 连接成功 | 窗口显示聆听；主入口为 Arco 已入会 | 每轮点名后回应 |
| 再次点击主入口 | 找回已有窗口 | 不创建第二会话，不误触离会 |
| 收起悬浮窗 | 隐藏窗口；主入口保留已入会状态 | AI 与转写继续 |
| 取消 / 请 Arco 离会 | 关窗；主入口回到邀请 | 停止语音、恢复系统输入，转写继续 |
| 结束会议 / 退出应用 | 关闭参会窗 | 清理语音会话和音频路由 |
| 录音启动失败 | 关闭未完成的参会窗，主界面显示错误 | 不保留空会话 |
| 语音连接失败 | 参会窗明确失败，可重试或收起 | 不自动反复重连或重复接管设备 |
| 从历史页邀请 | 使用当前录制，或新建当前会议 | 不把新音频追加到所查看的历史 |

音频组件在首次引导提前配置、允许跳过，之后可在设置补齐。邀请入口不触发驱动安装。

## 音频与自动恢复

```text
系统音频 ───────────────────────→ GPT-Live 聆听
现场麦克风 ─────────────────────→ GPT-Live 聆听
现场麦克风 ─→ microphone-bridge ─┐
                                ├→ BlackHole 2ch → 会议软件的麦克风输入
GPT-Live 回复 ───────────────────┘
             └→ 本机扬声器 / 耳机
```

发送总线只取 recorder 的现场声道，不回送远端系统声道。麦克风与 AI 各预留 6dB 混音余量；系统采集排除 GPT Live 播放进程，现有麦克风 AEC3 保留。发送积压超过 200ms 时丢弃旧缓冲并继续，避免短暂调度延迟造成整条会议线路断开。

邀请成功后才接通虚拟麦克风。独立 bridge 先固定物理麦克风，再将 macOS 默认输入切为 BlackHole 2ch。Arco 离会、停止录制、网络失败和正常退出时恢复原输入。设备 UID、原音量写入恢复日志，进程锁防止多个实例争用；意外终止后的下一次恢复会检查当前设备，保留用户另选的设备。父进程关闭 stdin、SIGTERM 与显式 stop 均有退出路径；Tokio 的阻塞 stdin 不再阻止 worker 结束。

**飞书需要选择一次「与系统一致」**。入会前和会议中的麦克风小箭头都能打开设备菜单；之后由系统默认输入变化驱动切换。固定选择物理设备或 BlackHole 的会议应用不会遵循这个自动切换。Arco 没有已验证的跨版本飞书设备设置 API，不宣称能自动修改任意会议应用的内部选项。

只是打开 Arco、浏览历史、转写或未邀请 AI 时，不接管系统麦克风。扬声器始终保留物理输出；安装驱动后若系统提示音被自动分配到 BlackHole，会恢复到物理扬声器。退出不会卸载驱动，驱动留在系统里但不再被 Arco 用作默认输入。

保存的麦克风失效时，recorder 回退到可用物理默认麦克风并固定设备，拒绝把虚拟/聚合设备当作回退输入。麦克风改由 AudioDevice IOProc 采集实际 ASBD，避免蓝牙从 48k 切换为 24k 时 AVAudioEngine tap 格式不匹配导致进程崩溃。停止设备和销毁回调之后才释放 Rust 音频句柄。启动失败会重新展示主窗口与错误提示。

## 首次配置与真实截图攻略

首次引导的音频步骤提供可选配置，允许跳过；之后在“设置 → 聆听与记录”补齐。Arco 自动获取官方 BlackHole 2ch 0.7.1 安装包，验证固定 SHA-256 与签名，通过 macOS 管理员授权安装。安装授权后在 root 独占目录再次验证。用户无需自行到网站下载，当前没有把第三方驱动改名或随应用重新分发。

安装不从“邀请 Arco 入会”触发。Arco 录制、音频检测或安装期间互相阻止冲突操作；下载结束也复查。组件状态通过隔离的 worker 枚举 CoreAudio，UI 主进程不链接音频采集框架。

`MeetingAudioGuideView` 使用真实飞书截图：入会前入口采用用户提供的截图，会议中入口及设备菜单由电脑操作工具直接截取。截图像素保持原样，SwiftUI 只展示相关区域并叠加高亮框。不是绘制的假界面。图片位于 `Resources/MeetingAudioGuide`，同时提供入会前 / 会议中两个页签，首次设置显示、之后可重新查看。

## 验证证据与边界

工作产物在 `tmp_agent_output/20260911-agora-copilot/`：

- `real-audio-probe.txt`：实际 BlackHole 设备收到测试麦克风音与 AI 音，远端系统音未回送；默认设备恢复、并发所有者拒绝、强杀后的日志恢复通过。
- `live-model-test.txt`：合成的“阿可”点名语音经真实 GPT Live WebRTC 产生实际播放，观察到 speaking 音量状态，无错误。没有使用私人会议内容作测试输入。
- `route-lifecycle.txt`：真实 Process 加假 worker，离会关闭 bridge、重入会重新建立、停止录制清理。
- `real-microphone-bridge.txt`：实际物理 recorder、BlackHole 路由与停止流程；覆盖 stdin stop / SIGTERM。
- `stale-microphone.txt`：复现失效的已保存麦克风，确认回退成功，系统与现场音频持续采集。
- 安装后的 `installed-official-aura-card.png` 记录实际官方 Aura 卡片，未保留旧 Canvas 版本。真实界面已验证仅邀请弹窗、收起后主入口仍为已入会、同一会话找回、离会关窗并恢复邀请入口，转写保持运行。
- recorder 原生边界测试 6 个；Rust 语音测试 33 个；Swift 主合同 367 个断言、悬浮窗 73 个、本地化 26 个。签名、UI 与隔离 worker 框架边界通过。
- 安装后界面已确认原有 79 场会议、混合模式、组件就绪与真实截图攻略，以及主界面邀请打开独立窗口，真实 GPT Live 连接并接通会议麦克风。`official-aura-metal.png` 为官方着色器移植后实际 GPU 输出。旧应用 / 安装包移到废纸篓，清理清单见 `trashed-duplicates.json`，没有删除源码、转写或凭证。

真实远端参会人的接收听感、长时间漂移、多方抢话及不同耳机/会议版本仍需实地验收；上述设备与模型测试不能替代这些结果。电脑操作工具在飞书原生窗口上的点击持续返回 noWindowsAvailable，用户已手动选中“与系统一致”；没有据此把飞书远端端到端验收标为完成。

## 连续对话实验（未发布）

Agora 的 policy.ts 和 prompts.ts 均要求每轮重新点名。Arco 实验改为首次点名开启 60 秒连续对话窗口，只有实际非静音回复续期，支持主动结束、超时和转写修正。五项门控测试通过，但合成语音的真实 GPT Live 测试出现漏词、称呼误识别、背景回复及停止后继续说话，未达到发布标准。实验源码、转写与测试脚本保留在 `tmp_agent_output/20260911-agora-copilot/multiturn/`。v0.3.25 保持逐轮点名，不宣称已经实现可靠的多轮语境判定。
