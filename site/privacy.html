Privacy and data boundaries

Local-first, stated precisely.

Arco keeps the meeting record on your Mac and gives you explicit choices for speech processing and Agent context. “Local-first” does not mean every optional provider is local.

The short answer

Transcripts, notes, meeting state, and Agent bindings are stored locally. Arco does not save raw meeting audio. Speech can be processed on-device or sent to the cloud transcription provider you select. Agent questions are sent through the Codex or Claude CLI you select, with the current transcript and only the project workspace you explicitly attach.

Arco has no hidden “fully local” claim. On-device transcription can keep speech processing on the Mac. Codex and Claude remain their own services, and cloud transcription providers receive meeting audio when selected.

What is stored on the Mac

By default, Arco stores its meeting data under:

~/Library/Application Support/Arco/

  • Finalized transcripts are readable Markdown.
  • Meeting state, generated output, Agent session bindings, and saved-note state use local atomic sidecars.
  • Hand-written and Agent-saved notes remain independent Markdown files.
  • You can choose different local folders for transcripts and notes.
  • Previously used transcript locations remain readable in History.

What happens to meeting audio

Arco captures system audio and the selected room microphone while a meeting is active. It does not save raw PCM audio as a recording. Instead, audio is streamed into the speech-recognition path configured for that meeting.

On-device path

When you select on-device speech recognition and speaker separation, meeting speech is processed by workers on the Mac. Model downloads are explicit and occur before capture; Arco does not silently download a model after a meeting has started.

Cloud transcription path

  • Selecting Deepgram for speech recognition or speaker separation sends the active meeting audio to Deepgram.
  • Selecting Doubao Speech for either role sends the active meeting audio to Doubao Speech.
  • Selecting ElevenLabs for speech recognition sends the active meeting audio to ElevenLabs. Speaker labels can come from a separately selected diarization provider.
  • Cloud credentials are verified by the Rust backend and stored in macOS Keychain, not in transcripts or logs.

What Codex or Claude receives

Arco's Agent is the Codex CLI or Claude Code already installed and authenticated on the Mac. The composer makes the context boundary visible:

  • The current meeting transcript is always included.
  • A project workspace is included only after you select it with the native folder picker.
  • Changing the workspace creates a different context boundary and provider session.
  • Arco never uses a recency shortcut such as --last or --continue to select an unrelated conversation.
  • Codex transcript and workspace runs add a read-only macOS sandbox around the CLI process.

The selected CLI and its provider still have their own privacy, retention, and network behavior. Arco does not relabel that cloud-backed inference as local inference.

What Arco does not do

  • It does not send a bot participant into the meeting.
  • It does not save raw PCM meeting audio.
  • It does not silently add an unrelated folder or CLI conversation to context.
  • It does not turn Agent output into a confirmed fact, decision, or task without a user action.
  • It does not run a hidden stop-time batch pass that replaces the live transcript.
